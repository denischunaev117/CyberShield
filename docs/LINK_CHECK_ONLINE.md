# Онлайн-проверка ссылок: Google Safe Browsing

Серверная часть — `workers/link-check/worker.mjs`, самостоятельно размещённый
Cloudflare Worker. Адрес опубликованного обработчика:

`https://cybershield-link-check.chunaevdenis.workers.dev`

Интерфейс выпуска подключается к этому обработчику по HTTPS. Ключ Google
хранится в его Secret, а не в JavaScript сайта. QR и OCR продолжают работать
на устройстве: наружу передаётся выбранный адрес, не изображение и не весь
распознанный текст. Онлайн-запрос запускается только явным действием пользователя
после видимого уведомления о передаче полного адреса Worker и Google.

Это проверка по базе известных угроз Google, а не гарантия безопасности сайта.
Публикация интерфейса и готовность серверного обработчика — разные проверки;
успешный `/health` сам по себе не доказывает работу Google API.

## Установка и сохранность ключа

1. Открыть Worker `cybershield-link-check` в Cloudflare Dashboard → **Edit code**.
2. При первой установке заменить Hello World полным содержимым
   `workers/link-check/worker.mjs`, включая `export default createWorker();`.
3. В Settings → Runtime variables and secrets создать Secret с именем
   `GOOGLE_SAFE_BROWSING_API_KEY` и значением Google API-ключа. Не вставлять ключ
   в исходник, frontend, команды терминала, скриншоты или отчёты.
4. Ограничить ключ в Google Cloud только Safe Browsing API. Ограничение по HTTP
   referer сайта не подходит для серверного Worker.
5. Нажать **Deploy**, затем проверить `/health` и настоящие `POST /check`.
   `configured: true` показывает наличие секрета, а не его действительность.
6. Перед публичным использованием сверить условия некоммерческого использования
   и квоты проекта в Google Cloud. Платные планы автоматически не подключаются.

Используется `redirect: "manual"`. Cloudflare Workers не поддерживает режим
`"error"` и выбрасывает TypeError до отправки запроса. Если Google неожиданно
вернёт 3xx, обработчик сообщит об ошибке и не перейдёт по Location.

## Контракт обработчика v1

`GET /` и `GET /health` возвращают сведения о сервисе, `revision: 1`,
`configured`, `checks: ["google-safe-browsing"]` и `redirectsChecked: false`.
Ни ключ, ни проверяемый адрес в health-ответ не входят.

Для проверки используется `POST /check` с заголовками
`Content-Type: application/json` и
`Origin: https://denischunaev117.github.io`, тело:

```json
{ "url": "https://example.com/", "consent": true }
```

`consent: true` передаётся только после явного действия пользователя с видимым
уведомлением об онлайн-проверке. Пользовательский ввод автоматически не переводится.
Учётные данные в URL, IP-адреса и локальные имена не поддерживаются. Адрес без
протокола разбирается как HTTPS; это не проверка доступности HTTPS.

Ответ HTTP 200:

- `verdict: no_known_threats` — Google не вернул совпадений. Это не утверждение
  «ссылка безопасна» и не доказательство принадлежности домена организации.
- `verdict: dangerous` — Google вернул совпадение с базой угроз. UI предупреждает
  о возможной опасности, показывает типы из `threatTypes` и источник Google.
  Формулировка не должна обещать стопроцентную точность обнаружения.
- `provider: google-safe-browsing`, `checkedAt` — источник и время проверки UTC.
- `scope: submitted-url-only`, `redirectsChecked: false` — проверен только
  переданный адрес. Эти поля нельзя подменять или игнорировать при описании охвата.

Ошибки:

- HTTP 400 — неверный/неподдерживаемый адрес, тело запроса или отсутствие согласия.
- HTTP 403 — Origin не разрешён; HTTP 405 — метод не поддерживается;
  HTTP 415 — запрос не имеет JSON Content-Type.
- HTTP 429 с `verdict: unavailable`, `error: rate_limited`, `Retry-After: 60` —
  сработало ограничение повторных запросов обработчика.
- HTTP 503 с `verdict: unavailable` — нет ключа, ошибка/квота Google, тайм-аут
  или некорректный ответ провайдера. Нельзя выдавать старый либо зелёный результат
  вместо ошибки и нельзя молча заменять онлайн-проверку локальной эвристикой.

## Охват и перенаправления

Worker обращается исключительно к фиксированному API Google. Проверяемый сайт
не открывается, DNS, TLS-сертификат, HTTP-доступность, HTML, JavaScript, репутация
продавца и фактическая цепочка перенаправлений не исследуются. Сокращённая ссылка
проверяется как переданный URL; конечный адрес сокращателя этим не установлен.
Ссылка внутри параметра — содержимое строки, а не доказанный переход.

В v1 намеренно нет произвольного серверного `fetch` проверяемого сайта.
Без надёжной защиты фактического соединения от private/local/metadata адресов
и DNS rebinding такой механизм создаёт SSRF-риск. Предварительная проверка DNS
и последующий обычный fetch не гарантируют, что соединение использует тот же IP.
В документации TCP Sockets Cloudflare явно перечисляет блокировку private IP,
localhost и Cloudflare IP, но это само по себе не доказывает эквивалентную защиту
произвольного HTTP fetch. Раскрытие переходов требует отдельной реализации,
проверок и развёртывания, а не изменения надписи в интерфейсе.

Обычный HTTP, отсутствие схемы во введённой строке, дефис, международное имя
или похожее название сами по себе не являются ответом Google о вредоносности.
Локальный разбор остаётся дополнительным пояснением и не приписывается Google.

## Источник, точность и свежесть результата

Условия Safe Browsing требуют заметного уведомления до включения проверки и
при предупреждении: защита не идеальна, возможны как ошибочные предупреждения,
так и пропуски опасных сайтов. Предупреждение Google формулируется как возможная,
предполагаемая опасность, а не как безусловно установленный факт.

Для предупреждений, полученных от Google, обязательна атрибуция со ссылкой
https://developers.google.com/safe-browsing/v4/advisory:

- EN: `Advisory provided by Google`.
- RU: `Рекомендации, предоставленные Google` — формулировка официальной
  русскоязычной документации Google.
- BE: смысловой перевод атрибуции на белорусский с сохранением Google и ссылки.

Атрибуция не относится к локальным сигналам или предупреждениям других источников.
Дополнительные сведения о фишинге — https://www.antiphishing.org/,
о вредоносных страницах — https://developers.google.com/search/docs/monitor-debug/security/malware,
о нежелательном ПО — https://www.google.com/about/unwanted-software-policy.html.

Согласно условиям Google нельзя показывать URL как угрозу на основании сведений,
полученных более 30 минут назад. Интерфейс должен очищать либо перепроверять
просроченный результат; время ответа само по себе не продлевает его действие.
Результаты и проверяемые адреса в storage/историю/аналитику не записываются.

## Границы защиты сервиса и бесплатного использования

CORS разрешает браузерные запросы только с origin опубликованного сайта.
Это не аутентификация: внешний HTTP-клиент может подделать Origin.
Методы, JSON-формат и размер тела ограничены; тела запроса и ответа Google
ограничены 16/64 КиБ. Запрос Google имеет тайм-аут 8 секунд.

Адрес и ответ Google не включаются в ответ клиенту, логи, storage или кэш
приложения. Тексты исключений и ответы ошибок Google не пересылаются клиенту;
это предотвращает случайное раскрытие ключа через сообщения об ошибках.
Оператору отдельно следует учитывать настройки журналирования инфраструктуры.

Ограничение 10 запросов в минуту на IP и 120 суммарно действует в памяти одного
isolate Cloudflare. IP хранятся только в течение окна без постоянного хранилища.
Это не распределённый дневной лимит и не защита от всех злоупотреблений.
Нужны сверка квот Google и мониторинг доступности; CORS не заменяет такой контроль.
Наличие конкретной настройки квоты в аккаунте владельца здесь не подтверждено.

Google Safe Browsing API предоставляется бесплатно для некоммерческого
использования — по документации, не для продажи или получения выручки.
Для коммерческого применения Google направляет к Web Risk.
Числовая квота Google индивидуальна для проекта, видна в Console и здесь
не выдумывается. Документация Workers Free указывает 100 000 запросов в сутки
на аккаунт со сбросом в 00:00 UTC и лимит CPU 10 мс на вызов. Это условия
платформы, а не подтверждение настроек конкретного аккаунта или обещание
безлимитной доступности. При исчерпании квот интерфейс сообщает о недоступности
проверки, а не объявляет адрес безопасным.

Проверенные первоисточники:

- https://developers.google.com/safe-browsing/v4/usage-limits
- https://developers.google.com/safe-browsing/v4/usage-limits?hl=ru
- https://developers.google.com/safe-browsing/v4/terms
- https://developers.cloudflare.com/workers/platform/limits/
- https://developers.cloudflare.com/workers/runtime-apis/request/
- https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/

## Проверки

`npx tsx --test tests/link-worker.test.ts` проверяет контракт, подтверждённый
фишинг, отсутствие угроз, неверные ответы/HTTP/ошибки провайдера, защиту ключа,
согласие, ограничения ввода, CORS и частоту запросов. Модульный тест не заменяет
проверку развёрнутого Worker, поскольку Node и Cloudflare имеют разные runtime.

16 ноября 2026 года после замены `redirect: "error"` на `"manual"` и ручного
Deploy выполнены настоящие запросы к опубликованному Worker:

| Проверка                                              | HTTP | Фактический результат                               |
| ----------------------------------------------------- | ---- | --------------------------------------------------- |
| `/health`                                             | 200  | `configured: true`, сервис `cybershield-link-check` |
| `https://example.com/`, согласие есть                 | 200  | `no_known_threats`                                  |
| `http://testsafebrowsing.appspot.com/s/phishing.html` | 200  | `dangerous`, `SOCIAL_ENGINEERING`                   |
| Адрес без согласия                                    | 400  | `consent_required`                                  |
| Запрос с посторонним Origin                           | 403  | `origin_not_allowed`                                |

Это подтверждает живую серверную проверку после исправления несовместимости.
Проверки интерфейса, production-путей и публикация сайта подтверждаются отдельно.
Ключи, пользовательские сообщения и изображения в эти тесты не включались.
